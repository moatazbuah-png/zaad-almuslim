# معمارية زاد المسلم

## الهدف

يبدأ المشروع كتطبيق ويب ثابت سريع، مع فصل واضح بين الواجهة والمحتوى، حتى يمكن إضافة قاعدة بيانات وواجهات API لاحقًا دون إعادة بناء تجربة المستخدم.

## طبقات النظام

1. **العرض**: `index.html` و`style.css`.
2. **التفاعل**: JavaScript داخل الواجهة الحالية، مع `script.js` لبيانات المشروع.
3. **المحتوى**: بيانات القرآن والأذكار والحديث قابلة للنقل لاحقًا إلى JSON أو API.
4. **البيانات**: قاعدة مستقبلية للمستخدمين والتقدم والمصادر والمراجعات.
5. **التكامل**: خدمات الصلاة والصوت والبحث والذكاء الاصطناعي بعد توثيق مزوديها.

## نموذج المحتوى

كل مادة شرعية مستقبلية ينبغي أن تحمل:

- `id`
- `title`
- `text`
- `source`
- `author_or_organization`
- `published_at`
- `updated_at`
- `review_status`
- `language`

## حالات المراجعة

- `draft`: مسودة داخلية.
- `review`: بانتظار المراجعة.
- `published`: منشورة.
- `archived`: مؤرشفة ولا تظهر افتراضيًا.

## قواعد أمنية

- لا توضع مفاتيح API داخل ملفات الواجهة.
- تستخدم خدمات الصلاة والصوت من مزود موثق وقابل للاستبدال.
- يخزن تقدم المستخدم محليًا في MVP ثم ينقل إلى حساب آمن.
- تجمع بيانات الأطفال بالحد الأدنى وبالضوابط المناسبة.
- لا يصدر الذكاء الاصطناعي فتوى مستقلة.
