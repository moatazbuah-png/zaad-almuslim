# معمارية زاد المسلم

## الوضع الحالي
التطبيق PWA ثابت وMobile-first، مع واجهة رئيسية تاريخيًا كبيرة. الهدف هو التفكيك التدريجي دون كسر الـMVP.

## الطبقات
- **UI**: صفحات ومكونات العرض والتفاعل.
- **Application**: حالات المستخدم، التنقل، البحث، الإشعارات.
- **Content**: JSON/مصادر المحتوى مع metadata ومراجعة.
- **Platform**: PWA، التخزين المحلي، Service Worker، الصوت والإشعارات.
- **Optional backend**: يضاف فقط عند الحاجة للمحتوى أو المزامنة، وليس شرطًا للاستخدام الأساسي.

## قواعد مهمة
1. لا تعتمد الواجهة على مصدر بيانات واحد غير موثق.
2. لا تضع أسرارًا أو مفاتيح خاصة في JavaScript الذي يصل إلى المتصفح.
3. اجعل التخزين المحلي هو الافتراضي للبيانات الشخصية غير الحساسة.
4. أي مزامنة سحابية يجب أن تكون اختيارية ومحدودة البيانات.
5. اجعل مزود مواقيت الصلاة ومزود الصوت قابلين للاستبدال.
6. لا تجعل إعلانًا أو تحقيق دخل شرطًا للوصول إلى القرآن والأذكار الأساسية.

## خطة التفكيك
`index.html` → UI shell + routes
`script.js` → state/content/application modules
`data/content.json` → content catalog
`sw.js` → offline platform layer

## معايير القبول
- يعمل التطبيق بدون حساب.
- يعمل عند انقطاع الشبكة بعد أول تحميل.
- لا يفقد التقدم المحلي.
- كل محتوى ديني منشور له مصدر ومرجع مناسب.
- لا توجد أسرار في المستودع.
- تغييرات الواجهة لا تكسر البيانات المحلية القديمة.
