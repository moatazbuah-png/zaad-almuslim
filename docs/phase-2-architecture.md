# المرحلة الثانية — إعادة بناء المنظومة

## الهدف
تحويل الـMVP إلى بنية وحدات قابلة للتوسع مع الحفاظ على الوظائف الحالية.

## الوحدات
- `core/`: الحالة، التخزين، الأحداث، الأخطاء.
- `content/`: تحميل والتحقق وفهرسة المحتوى.
- `features/quran/`: القراءة والعلامات وآخر موضع.
- `features/adhkar/`: التصنيفات والعداد والتقدم.
- `features/hadith/`: العرض والبحث والمراجع.
- `features/prayer/`: المواقيت والقبلة والتنبيهات.
- `features/search/`: البحث الموحد العربي.
- `ui/`: مكونات العرض وإدارة التنقل.

## قواعد المرحلة
1. لا تُدخل بيانات حساسة في التخزين المحلي دون حاجة.
2. لا يعتمد المحتوى الشرعي على نصوص مولدة آليًا.
3. كل ميزة جديدة يجب أن تعمل دون حساب مستخدم إن لم تكن المزامنة ضرورية.
4. لا يكسر التطوير الوظائف الحالية.
5. كل تغيير جوهري يمر باختبار آلي أو smoke test.
6. المحتوى الأساسي مجاني.

## ترتيب التنفيذ
1. فصل الحالة والتخزين.
2. فصل المحتوى والبحث.
3. فصل الميزات واحدةً واحدة.
4. ربط الواجهة بالمكونات الجديدة.
5. إضافة اختبارات وظيفية.
6. تحسين الأداء وPWA.
7. مراجعة أمنية وإصدار تجريبي.
